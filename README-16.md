# Panther Desktop

نسخه‌ی ویندوز پنتر. یک پنجره، یک دکمه، بدون نصب درایور و بدون دسترسی ادمین.

## این نسخه چطور کار می‌کند

موتور به صورت یک برنامه‌ی جداگانه بالا می‌آید و یک **پروکسی SOCKS5 روی `127.0.0.1:1819`** می‌سازد. برنامه فقط آن را اجرا و مدیریت می‌کند. یعنی نه درایور TUN لازم است، نه دسترسی مدیر، و نه چیزی در سیستم نصب می‌شود.

بعد از اتصال، همان آدرس را در مرورگرت وارد کن. در فایرفاکس از Settings → Network Settings، و در کروم با افزونه‌هایی مثل Proxy SwitchyOmega.

## موتورها

| موتور | وضعیت در این نسخه |
|---|---|
| **Aether** | ✅ فعال |
| **Global** | ✅ فعال (دو مرحله‌ای، از داخل Aether) |
| **Prowl** | ⏳ هنوز همراه این نسخه نیست |

اگر موتوری همراه نسخه نباشد، برنامه صادقانه همان را می‌گوید و چیزی را وانمود نمی‌کند.

### چرا Global دو مرحله‌ای است

موتور Global تنهایی روی شبکه‌های هدف این برنامه راه پیدا نمی‌کند: لیست سرورهایش را از میزبانی می‌گیرد که از آنجا در دسترس نیست و سرورهای خودش هم فیلترند. پس به‌جای اینکه مستقیم به شبکه وصل شود، **از داخل تونل Aether** دیال می‌شود. برنامه اول Aether را روی `1819` بالا می‌آورد، بعد Global را روی `1820` که ترافیکش از اولی رد می‌شود، و آدرسی که به کاربر می‌دهد `1820` است.

### انتخاب کشور خروجی

وقتی Global انتخاب شود یک فهرست کشور کنارش ظاهر می‌شود. «خودکار» یعنی موتور خودش انتخاب کند. کشوری که در آن لحظه ارائه نشود خطا نیست؛ موتور به حالت خودکار برمی‌گردد. فهرست اولیه همان فهرست نسخه‌ی اندروید است.

به همین دلیل اتصال با Global بیشتر طول می‌کشد. و اگر مرحله‌ی دوم بالا نیاید، مرحله‌ی اول هم خاموش می‌شود؛ یک زنجیره‌ی نیمه‌کاره از بیرون شبیه اتصال سالم است و این بدترین حالت ممکن است.

## چرا فایل‌ها صاف در ریشه‌اند

این پروژه از گوشی نگهداری می‌شود و آپلودکننده‌ی وب گیت‌هاب نمی‌تواند پوشه بسازد. پس مخزن شکل صاف و قابل‌آپلود دارد و `assemble.sh` هنگام بیلد ساختار واقعی Tauri را می‌سازد. لوگو هم به شکل متن base64 در `logo.b64` است و `make-icons.py` همه‌ی آیکون‌ها را از رویش تولید می‌کند، چون فایل باینری از گوشی درست آپلود نمی‌شود.

| فایل در ریشه | جایگاه واقعی |
|---|---|
| `app.index.html`, `app.styles.css`, `app.main.js` | `src/` |
| `tauri.conf.json`, `Cargo.toml`, `build.rs` | `src-tauri/` |
| `capabilities.json` | `src-tauri/capabilities/default.json` |
| `engines.rs`, `main.rs` | `src-tauri/src/` |
| `live.rs` | `src-tauri/tests/` |
| `logo.b64` | از رویش `src-tauri/icons/*` و `src/logo.png` ساخته می‌شود |

## ساخت

بیلد روی GitHub Actions انجام می‌شود، پس برای ساختن به هیچ ویندوزی نیاز نیست.

- یک تگ `v*` بزن، یا از تب Actions همان ورک‌فلو را دستی اجرا کن.
- CI اول منطق موتور را روی لینوکس تست می‌کند، بعد ساختار را می‌چیند، هسته‌ی Aether را از ریپوی رسمی‌اش می‌گیرد، checksum را بررسی می‌کند، و بدون هسته اجازه‌ی بیلد نمی‌دهد.
- خروجی یک نصب‌کننده‌ی NSIS است که بدون دسترسی ادمین نصب می‌شود.

برای بیلد محلی روی ویندوز یا لینوکس:

```
python -m pip install pillow
bash assemble.sh
cargo tauri build
```

## تست‌ها

`engines.rs` عمداً هیچ وابستگی‌ای به Tauri ندارد تا بشود جدا کامپایل و تستش کرد. کنارش `live.rs` هسته‌های قلابی را واقعاً اجرا می‌کند که پورت باز می‌کنند، و سه چیز را می‌سنجد: اینکه اتصال تک‌مرحله‌ای بالا بیاید، اینکه زنجیره‌ی دو مرحله‌ای هر دو پایه‌اش بالا بیاید و روی پایه‌ی بیرونی سرویس بدهد، و اینکه نبودن هسته‌ی دوم کل زنجیره را پایین بیاورد. CI همه را قبل از بیلد ویندوز اجرا می‌کند.

## نکته‌ها

- اولین اتصال با Global تا حدود یک دقیقه طول می‌کشد، چون دو تونل پشت سر هم بالا می‌آیند.
- نصب‌کننده امضای دیجیتال ندارد، پس ویندوز ممکن است هشدار SmartScreen بدهد. این درباره‌ی ناشناس بودن امضاست، نه محتوای برنامه.
- پروکسی SOCKS رمز عبور ندارد و فقط روی `127.0.0.1` باز می‌شود. آن را روی شبکه باز نکن.
